# RFC-0001: Vendor-neutral Peppol interoperability contracts

Status: accepted for staged implementation.

## Problem

Existing open-source components implement Peppol discovery, publishing, validation, and AS4 delivery.
The official Testbed serves accreditation and network testing. Developers still lack a small,
deterministic contract runner that can execute the same observable scenario against different SMP or
AP products and retain CI-friendly evidence.

## Decision

Peppol Interop Lab separates three concerns:

1. Versioned, vendor-neutral YAML scenarios describe observable inputs and expectations.
2. Target adapters translate generic actions to standard wire protocols or vendor control planes.
3. Local fixtures provide deterministic peers and failures without contacting production systems.

Scenario results are `PASSED`, `FAILED`, `SKIPPED`, or `ERROR`. Missing capabilities produce a skip.
HTTP and protocol failures remain observable adapter results so scenarios can assert them; failures of
the laboratory itself are errors.

## Stages

Stage one establishes the scenario API, adapter SPI, runner, HTTP fixtures, reports, safety controls,
starter SMP contracts, and diagnostic AS4 wire contracts.

Stage two adds an authoritative DNS fixture, generated test PKI, phase4-signed/encrypted AS4 messages,
receipt verification, payload-integrity mutations, and duplicate-message tests.

Stage three adds phoss SMP provisioning/cleanup, bring-your-own-test-certificate phoss AP end-to-end
flows, reusable container environments, and adapters contributed by other implementations.

## Non-goals

- Claiming OpenPeppol accreditation or certification.
- Shipping production Peppol keys or certificates.
- Reimplementing phoss SMP, phoss AP, phase4, or document validation.
- Encoding vendor retry policy as a Peppol protocol requirement.
- Enabling production network access by default.

## Compatibility

Scenario formats remain versioned independently from the CLI. Specification versions are explicit in
every scenario so a future Peppol revision does not silently change historical results.
